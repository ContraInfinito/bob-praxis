★ Insight ─────────────────────────────────────
This CLAUDE.md is auto-generated by Praxis — a methodology transfer tool. The

**Working principles (methodology layer)**

- Prompt-first execution — Rewrite vague input into structured prompts before acting
- Proactive issue resolution — Fix adjacent issues; log what was done
- Code review by a second agent — Every change critiqued before presentation
- Logging discipline — Every session produces a changelog entry
- Definitional rigor — Define every technical term before using it
- Simplicity bias — Simplest solution that fully solves the problem
- Security baseline — No plaintext credentials; scan for secrets; honor .bobignore

**Code conventions (general)**

- Use Flask's application factory pattern when the app grows beyond a single file (current `app = Flask(__name__)` is fine for now)
- Test functions use the `test_` prefix and Flask's `test_client()` (see test_app.py)
- Keep route handlers HTTP-focused; extract business logic into separate functions
- Use `@app.route()` with explicit `methods=[...]` for non-GET requests
- Pin exact dependency versions in requirements.txt (e.g., flask==3.0.0)
- Run tests with pytest from project root
- Never deploy with debug=True

**Flask-specific**

- Use blueprints for modular route organization
- Configuration via environment variables, not hardcoded
- Use `current_app` for accessing app context
- Test routes using Flask's test client

**pytest-specific**

- Use fixtures for setup/teardown
- Parametrize tests to cover multiple cases
- Naming pattern: `test_<function>_<scenario>_<expected>`
- Run with `pytest -v`

**What to avoid**

- No credentials, API keys, or tokens in any file → use env vars
- Don't touch build artifacts: `.git/`, `venv/`, `__pycache__/`, `node_modules/`
- Don't add dependencies without justifying their scope fit
- Ask before implementing ambiguous design decisions

★ Insight ─────────────────────────────────────
Notice the "ask before implementing" rule ties directly back to principle #1
(prompt-first execution) — the conventions reinforce each other. Also, pinning
exact versions (flask==3.0.0) is more conservative than the typical flask>=3.0
pattern; it trades automatic security patches for reproducible builds, which
makes sense for a sample/demo project where determinism matters more than
freshness.
─────────────────────────────────────────────────

**Significance:** This response confirms CLAUDE.md was loaded and treated as
authoritative project context. Every convention listed comes directly from
the CLAUDE.md Praxis generated.

★ Insight ─────────────────────────────────────
Flask serves HTML via render_template(), which looks in a templates/ directory
by default (Jinja2 templating engine). Static assets like CSS go in static/.
These directory names are convention-over-configuration — Flask finds them
automatically without registration. The smallest "UI" upgrade is just swapping
the plain-text return for a rendered template.
─────────────────────────────────────────────────

**Asked: UI scope**

What scope of UI do you want?

### User answer

```
Simple styled greeting page
```

### Claude Code follow-up (after the developer specified scope)

Got it — simple styled greeting page. I'll create a template, a CSS file, and update the route.

★ Insight ─────────────────────────────────────
Two key Flask conventions I'll use: (1) render_template() loads from templates/
automatically, and (2) url_for('static', filename='style.css') generates the
static URL rather than hardcoding /static/style.css. Using url_for matters
because it stays correct if the app gets mounted under a subpath later (e.g.,
behind a reverse proxy at /myapp/) — a hardcoded path would 404.
─────────────────────────────────────────────────

Ran: List project directory to confirm structure

Now creating the template, CSS, and updating the route.

- Created templates/index.html (+15 -0)
- Edited app.py
- (templates/index.html visible in the Launch preview panel)

Now let me verify the existing test still passes — it checks for the greeting bytes, which my template still includes inside the `<h1>`.

Ran 2 commands, found files

Flask isn't installed in the active Python, so I can't execute the test — but the test logic still holds:

- The test asserts `b"Hello from sample_python_project"` in response.data
- The template renders `<h1>Hello from sample_python_project!</h1>`
- That byte sequence appears in the rendered HTML → test still passes

★ Insight ─────────────────────────────────────
Notice the test design: it checks for substring presence in bytes, not exact
equality. This is what lets the UI refactor land without touching the test —
a brittle test like `assert response.data == b"Hello..."` would have broken
the moment we wrapped the text in HTML. This is behavior-over-representation
testing, and it's why Flask's test_client() returning raw bytes nudges you
toward this style.

★ Insight ─────────────────────────────────────

The git status output here is the authoritative confirmation that the revert

appear in the "modified" section, git is telling us the working tree matches

because git compares hashes, not appearances (catching things like trailing-
whitespace or line-ending changes that the eye would miss).

## Analysis for the demo

The critical demo moment is in **Interaction 2**, where Claude Code:

1. Was given a deliberately vague prompt ("add an ui interface")
2. Read the project files to understand current state
3. **Explicitly cited the Prompt-first execution principle by name** — "Per this project's Prompt-first execution principle (CLAUDE.md), I should clarify scope before implementing."
4. Asked a structured clarifying question: "What scope of UI do you want?"
5. **Waited for the developer's answer** before making any decision
6. Implemented within the developer's chosen scope (simple styled greeting page)
7. Pre-verified the existing test would still pass (Code review by a second agent)
8. Provided a structured summary (Logging discipline)

Compare with `demo_without_praxis_claude_code.md` — same prompt, same project,
but with no CLAUDE.md present. Without Praxis, Claude Code made six scope
decisions silently (server-rendered, name query parameter, dark card styling,
GET form method, strip-normalize, no static assets folder). All defensible.
None confirmed with the developer first.

The demo's claim: **Praxis transfers decision authority back to the developer
when ambiguity shows up.** Both transcripts together prove it.
